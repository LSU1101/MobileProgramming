# 어디서돈썼지도 — 정식 앱 개발 인계 문서

이 문서는 검증 앱(이 저장소) 작업에서 나온 **결정 사항, 검증 결과, 알게 된 함정**을 정식 앱 개발 세션에 넘기기 위한 것입니다.
새 Claude Code 세션에서는 이 문서를 먼저 읽고 시작하세요.

---

## 0. 한 줄 요약

토스 결제 알림을 받은 순간의 GPS 위치는 실제 매장에서 **100m 안에 충분히 들어온다** (기준 좌표가 있는 47건 중 47건).
따라서 정식 앱은 **"알림 수신 → 결제 판별 → 즉시 GPS 1회 측정 → 근처에서 가맹점명으로 장소 검색"** 구조로 간다.

| 배포 | **시연용 직접 설치** (Play 스토어 출시 안 함) | 백그라운드 위치 심사, 배터리 예외 정책, 개인정보처리방침 제출이 필요 없음 |

| 장소 검색 | **카카오 로컬 API** (키워드 검색 + 좌표 반경) | REST 키는 시연용이라 앱에 포함하고 콘솔에서 사용량 제한 |

## 2. 검증 결과 (팀원 2명, 2026-10-14 ~ 11-11)

> 집계 수치만 담았다. 원본 CSV는 팀원의 실제 알림, 결제, 위치 기록이라 저장소에 올리지 않는다.

| 지표 | 결과 | 해석 |
|---|---|---|
| 실결제 알림 | 86건 (+ 결제 실패 3, 취소 2) | 목표 40건 초과 달성 |
| 위치 획득 성공률 | **85 / 86 (98.8%)** | 실패 1건은 지하철 이동 중 시간 초과(`TIMEOUT_10S`) |
| 위치 획득 시간 | 중앙값 **0.9초**, 상위 10% 3.4초, 최대 10초 | 10초 제한은 적절. 넉넉히 잡으려면 15초 |
| 위치 정확도 | 중앙값 ±12.5m, 상위 10% ±24.7m | |
| **알림 좌표 ↔ 매장 앞 기준 좌표 거리** | 47건 중 **47건이 100m 이내**. 중앙값 **3.1m**, 상위 10% 11.5m, 최대 36.9m | 가설 지지 |
| 캐시 위치(lastKnown) ↔ 기준 좌표 | 중앙값 14.7m, **47건 중 5건이 100m 초과, 최대 2.2km**. 캐시 나이 중앙값 2.2분 | **캐시 위치는 믿을 수 없음 → 새로 측정해야 함** |
| 백그라운드 동작 | 86건 중 80건이 앱 화면이 꺼진 상태에서 기록 | 알림 리스너 + 백그라운드 위치 권한으로 충분 |
| 토스 알림 → 앱 도착 | 중앙값 0.04초, 최대 0.7초 | |
| 결제 → 알림 지연 | **측정 실패** | 82건 모두 "실제 결제 시각"이 수신 시각 기본값 그대로였음(아무도 수정하지 않음). 체감상 즉시 |
| 온라인 결제 비율 | 86건 중 25건 (**약 29%**) | 결제대행사 가맹점이 대부분 (§3.3) |
| 토스 알림 중 결제 비율 | 2,025건 중 91건 (**4.5%**) | 증권, 이벤트, 송금 알림이 대부분 → **결제로 판별된 알림만 위치 측정** |

### 결과 해석 시 주의
- **기준 좌표도 같은 폰의 GPS다.** 알림 직후(중앙값 21초 뒤) 같은 자리에서 찍어서 오차가 같은 방향으로 날 수 있다. "실제 매장과 3m"가 아니라 "측정값끼리 일치"에 가깝다. 다만 정확도(±12m)와 장소 검색 반경(수백 m)을 생각하면 장소 매칭에는 충분하다.
- 표본은 팀원 2명이고, 학교·집 근처 편의점과 식당 위주다. 지하상가나 대형 쇼핑몰 표본은 적다.

## 3. 토스 알림에 대해 알게 된 것

### 3.1 확인된 알림 형식 (파서 테스트에 모두 들어 있음)

| 종류 | title | text (본문) | 비고 |
|---|---|---|---|
| 타 카드사 결제 | `20,000원 결제` | `하나체크 \| 가맹점(일시불)` | 토스 "카드 알림 받기" 경유 |
| 결제 취소 | `20,000원 결제 취소` | `하나체크 \| 가맹점(일시불)` | |
| **결제 실패** | `2,500원 결제 실패` | `우리체크 \| 가맹점(일시불)` | 잔액 부족. **결제로 세면 안 됨** |
| 토스뱅크 체크카드 | `10,000원 결제` | `토스뱅크 체크카드 \| 가맹점`<br>`잔액 740,300원` | **잔액 줄을 금액으로 읽으면 안 됨** |
| 토스페이 | `17,000원 결제 완료` | `토스페이머니 ・ 가맹점`<br>`보너스 포인트 적립 가능` | 구분자 `・`(U+30FB 등 여러 종류). "적립" 단어가 있어도 결제 |
| 포인트 적립 | `포인트 적립` | `토스페이 결제 혜택으로 14원 받았어요` | 결제 아님 |
| **캐시백 (파서 미지원)** | `100원 캐시백 🎉` | `4,000원 결제 \| 가맹점`<br>`잔액 284,078원(토스뱅크 체크카드)` | 금액은 맞게 읽지만 **가맹점과 카드가 비어 나옴**. 정식 앱 파서에서 지원할 것 (§3.4) |

### 3.2 걸러야 하는 알림
- **진행 중(ongoing) 알림:** 토스 만보기 Live Activity가 걸음 수가 바뀔 때마다 다시 올라온다. `sbn.isOngoing`이면 무시한다.
- **묶음(그룹 요약) 알림:** `FLAG_GROUP_SUMMARY`. 내용이 비어 있다.
- **증권, 이벤트, 출금, 송금 알림:** 토스 알림의 95%다. 파싱해서 결제·취소·실패가 아니면 **위치를 측정하지 않는다** (검증 앱은 모든 토스 알림에서 측정해서 배터리를 낭비했다).

### 3.3 온라인 결제 판별 단서
- 결제대행사 가맹점명: `구글페이먼트코리아`, `네이버파이낸셜`, `네이버페이`, `steam-degica`, `한국정보인증`, `(자동결제)` 접미사, OTT·웹소설 등 구독 서비스
- 가맹점명이 결제대행사면 **장소 매칭을 건너뛰고 "온라인" 처리**하는 게 맞다
- 택시(`카카오T택시_가승인`)는 결제 시점 위치가 승차 위치나 하차 위치다. 별도 처리를 고민할 것

### 3.4 파서에서 아직 남은 일
- [ ] 캐시백 형식: 결제 줄 자체에 `| 가맹점`이 붙은 경우 가맹점 분리, 잔액 줄 괄호 안의 카드명 추출
- [ ] 송금 받음(`10,000원 받았어요`)이 포인트(`POINT`)로 잘못 분류됨 (분석 영향 없음)
- [ ] 해외·외화 결제(`USD 12.99` 등): 금액 패턴이 "N원"만 인식 → 실제 알림 원문을 받으면 추가
- [ ] 같은 결제가 두 번 오는 경우(검증 기간에는 0건)의 중복 제거 기준

## 4. 설치, 권한, 기기에서 알게 된 것

- **Play 프로텍트 차단:** 브라우저나 메신저로 받은 APK 중 알림 접근 권한을 쓰는 앱은 "기기 보호를 위해 앱 차단됨"으로 막힌다. Play 스토어 → Play 프로텍트 설정 → 앱 검사 끄기 후 설치. **시연 기기는 `adb install`로 미리 설치**할 것.
- **Android 13+ "제한된 설정":** 직접 설치한 앱은 알림 접근이 막힌다. 앱 정보 → ⋮ → 제한된 설정 허용. `adb install`이면 필요 없음.
- **권한 흐름:** 알림 접근 → 위치(정확한 위치) → 백그라운드 위치("항상 허용", Android 11+는 설정 화면으로 이동) → 배터리 최적화 제외. 순서가 중요하다(백그라운드 위치는 일반 위치 다음에만 요청 가능).
- **앱 상태 값:** 알림 리스너가 연결돼 있으면 화면이 꺼져 있어도 프로세스 중요도가 `FOREGROUND_SERVICE(125)`로 나온다. "앱이 켜져 있었다"로 해석하면 안 된다.
- **"강제 종료"하면 알림 리스너가 꺼진다.** 최근 앱 목록에서 지우는 것은 괜찮다.
- **업데이트할 때 서명 키가 다르면 앱을 지워야 하고 데이터가 사라진다** → 팀 공용 서명 키 필수 (§6).

## 6. 정식 앱 설계 초안 (1주차에 확정)

### 데이터 흐름
```
토스 알림 → [①] 필터(진행 중·묶음 제외) → 파싱 → 결제/취소/실패가 아니면 종료
         → [②] GPS 1회 측정(10~15초)
         → Room에 Transaction 저장 (오프라인에서도 유실 없음)
         → [②] 가맹점명 + 좌표로 카카오 장소 검색 → Place 연결 (결제대행사면 "온라인")
         → [④] Firestore 동기화 (WorkManager)
         → [③] 지도, 내역, 통계 화면
```
- **기기 DB(Room)가 원본이고 Firestore는 동기화 대상이다.** 알림이 백그라운드에서 오기 때문에 네트워크 없이도 먼저 저장되어야 한다.
- Firestore 경로 `users/{uid}/transactions/{id}`. 보안 규칙으로 본인 데이터만 읽고 쓸 수 있게 한다.

### 모듈 간 약속 (1주차에 이것부터 고정하면 병렬 개발 가능)
```kotlin
interface PaymentSource          { val payments: Flow<ParsedPayment> }                          // ①
interface LocationProvider       { suspend fun capture(): LocationResult }                        // ②
interface PlaceResolver          { suspend fun resolve(merchant: String, near: LatLng?): Place? } // ②
interface TransactionRepository  { /* 저장·조회·수정·동기화 */ }                                  // ④
```
③은 이 인터페이스의 가짜 구현으로 화면을 먼저 만든다.

### 핵심 모델 초안
- `Transaction`: id, 금액, 가맹점명(원문), 카드, 결제방식, 종류(결제/취소/실패), 결제 시각, 위치(위도·경도·정확도), placeId, 온라인 여부, 사용자 수정 여부
- `Place`: 카카오 장소 ID, 이름, 좌표, 카테고리, 주소

### 서명 키 (중요)
구글 로그인(Firebase에 **SHA-1** 등록)과 카카오맵(**키 해시** 등록)이 모두 앱 서명 키에 묶인다.
→ **팀 공용 키 하나**를 만들어 로컬과 CI 빌드 모두 같은 키로 서명한다. 키 파일과 비밀번호는 GitHub Secrets에 두고, 로컬은 `local.properties`(커밋 금지)로 관리한다.

### API 키 관리
- 카카오 네이티브 앱 키, REST 키, `google-services.json`은 `local.properties`와 GitHub Secrets로 관리하고 커밋하지 않는다
- 카카오 개발자 앱 1개를 팀이 같이 쓰고, 패키지명과 키 해시를 등록한다

## 8. 개발 환경과 Claude Code 활용

| 환경 | 용도 |
|---|---|
| **로컬 Mac** (Claude Code CLI / Desktop + Android Studio) | 메인 개발. Gradle 빌드, 에뮬레이터, `adb`, logcat을 Claude가 직접 다룬다 |
| **Remote Control** (`claude remote-control`) | 밖에서 폰으로 로컬 세션 조작 |
| **클라우드 세션** | 작은 작업(파서 규칙, 문서, 테스트). 기본 환경은 `dl.google.com`이 막혀 Android 빌드가 안 된다 → 환경 설정 Allowed domains에 `dl.google.com`, `maven.google.com` 추가 |

시작할 때 할 일:
1. `/init`으로 `CLAUDE.md` 작성: 모듈 경계, 코딩 규칙, "알림 원문 저장 금지" 같은 결정 사항. Claude 리뷰어도 이 파일을 기준으로 리뷰한다
2. 큰 기능은 **Plan 모드**로 설계부터 합의
3. 자주 쓸 것: `/code-review`(푸시 전), `/security-review`(결제·위치를 다루므로 필수), `/simplify`, `run`(앱 실행 확인). 디자인 쪽은 Figma 스킬(`figma-design-to-code`), `design:ux-copy`(권한 요청 문구)
